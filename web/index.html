Alambic module tool

Look inside an Ornament & Crime module running the Alambic firmware, and install a new firmware on it. Connect the module to this computer with a USB cable; use Chrome or Edge on a desktop computer.

Look inside the module

not connected

The browser lists the module twice under the same name: pick the second one. If the page says it is the wrong one, click Connect again and pick the other. Restart into install mode does what the PROGRAM button does: the module stops and waits for a firmware (see below); installing one, or switching the module off and on, brings it back.

For developers

This is cargo probe in the browser: the module's second USB serial port (the first carries the text log), opened through Web Serial. Any baud rate works except 134, which restarts the module into its bootloader. Restart into install mode is cargo probe reboot.

Screen

A copy of what the module's display shows. With live, it refreshes about ten times a second.

For developers

cargo probe screen (as text; --png screen.png for an image).

Set an output

mV

Holds the chosen output at a fixed voltage, whatever the running app does: handy to check a cable or tune an oscillator. 1000 mV is 1 V; the outputs go from −3 V to +7 V. Release gives the output back to the app; disconnecting releases every output.

For developers

cargo probe out A 1000 holds the output until Enter, printing the inputs meanwhile. The value goes through the module's own calibration, as the app's values do.

Apps

The apps the module runs, and the settings of the one chosen, as its screen shows them. Change a value and it takes effect at once, exactly as if you had turned the knob: the module keeps it within the same limits, and says so if another setting narrowed it. The button after a setting a CV input can move shows its input (CV while none, +CV2 as the module's screen marks it); click it to open (▸) or close (▾) the same fields as the module's input submenu: input, scale, shift, bounds, effect. Each change is sent at once; closing the panel keeps what is set. The buttons under them are the module's four slots, left to right, the one on its screen filled: click one to show it there and here, ✕ to empty it (NOTHING in it, its outputs free). Run in slot @N puts the chosen app in that slot, the one shown, on the outputs no other app uses; NOTHING, last in the list, empties it too. Under its settings, where each of its outputs goes and which jack each input it reads comes from, as its routing page sets them (journal/D-046).

For developers

cargo probe apps, cargo probe app ratchet, cargo probe set ratchet prob 50, get, act, select (journal/D-043). The page parses and writes values with the command line's own code (oc_probe::apps), so a value reads and is typed the same in both.

Timing

How busy the module is. It does its work in a cycle repeated every millisecond; the table shows, for each part of that cycle, how many times it ran and how long it took, in microseconds (shortest, average, longest). To measure one thing: click Clear, do it on the module (change app, turn a knob), then click Read.

For developers

cargo probe stats (--fresh 5 clears, waits 5 s, then reads; --watch 2 repeats). The rows are the stages of oc_core::profile::Stage, timed on the core's cycle counter; period is the time between two ticks and the jitter table its spread around 1 ms. See “Measuring costs” in docs/agents/firmware.md.

Install a firmware

      
    
        
  1. Choose the firmware file you were given or downloaded: either the file named
          oc-firmware, without extension (preferred: the page can check it fully),
          or a .hex file.
    2. 
        
  2. The page checks it before anything is written and shows its fingerprint.
          Compare it with the one published with the firmware: if they differ, do not install.
    3. 
        
  3. Tick the box under the fingerprint, then click Install. If the module is connected above, it
          switches to install mode by itself, and so does one whose port was picked above even when
          it runs a firmware of another version (the page then restarts it at 134 baud); otherwise
          press the small PROGRAM button on the Teensy board first.
    4. 
        
  4. In install mode the module shows up as another USB device, the Teensy's installer
          (HalfKay, 16c0:0478). The first time only, Chrome asks whether this
          page may use it: pick it in Chrome's list (it is not a file). Keep the cable plugged
          until the page says it is done; the module then restarts on the new firmware.
    5. 
      

      

        
      

      

      

        
      

      

        
        
        
      

      
This cannot damage the module: the Teensy's installer lives on a separate
        chip that a firmware cannot erase, and the PROGRAM button always brings it back. If an
        install fails, press PROGRAM and try again.

      

        For developers
        
The preferred file is the firmware ELF,
          target/thumbv7em-none-eabihf/release/oc-firmware after
          cargo xtask build: the page runs on it the same checks as
          cargo xtask flash (xtask::validate), and the fingerprint is
          the ELF's SHA-256 (elf sha256). An Intel HEX file
          (cargo xtask hex, the CI artefact, or another Teensy 4.0 firmware) gets
          reduced checks: valid records and checksums, an end record, every byte inside the
          application flash and none twice, and the boot header the boot ROM reads (FCB, IVT,
          boot data); its fingerprint is the .hex file's SHA-256 (hex
          sha256). The page then writes the flash through the HalfKay bootloader (USB
          16c0:0478) over WebHID, as teensy_loader_cli does.
